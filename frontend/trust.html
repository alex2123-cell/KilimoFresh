Trust & security

Check it yourself

KilimoFresh runs its own public key infrastructure. It encrypts the connection, signs every receipt, and protects the admin area. This page shows the certificates and lets you verify any receipt.

Verify a receipt

Enter a requisition reference number. Your browser fetches the receipt and checks its digital signature against our public key. Nothing is taken on trust from the server.

Try to forge it

This is the exact text that was signed. Change any character, for example the total, and the signature stops matching.

Where the keys are used

        

        

          
Encrypted connection
The server certificate enables HTTPS (TLS), so phone numbers and orders cannot be read or changed in transit.

          
Signed receipts
Each receipt is signed with RSA and SHA-256. A valid signature proves who issued it and that not one character has changed.

          
Signed admin sessions
After sign-in the admin holds a token signed with the same private key. A forged or edited token is rejected.

        

      

    


    

      

        

          
Under the hood

          
Core components of this web application

        

        

          
1. Client · presentation tier
Your browser. Semantic HTML5 pages, one CSS style sheet, and JavaScript ES modules that build the interface through the Document Object Model (createElement, event listeners, <dialog>, localStorage, Web Crypto).

          
HTTPS REQUEST ↓ ↑ JSON RESPONSE

          
2. Web server
Node.js with Express. Serves the static pages, terminates TLS with the server certificate, and adds security headers and rate limits.

          
ROUTES ↓ ↑ RESULTS

          
3. Application logic · REST API
Routes under /api validate input, estimate costs, issue reference numbers, sign receipts and check admin sessions.

          
READ ↓ ↑ WRITE

          
4. Data store
JSON collections: produce catalog (D1), requisitions (D2), delivery zones (D3), grower applications, messages and admin users.
